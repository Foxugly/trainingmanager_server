## 🔴 Bugs (à corriger en priorité)

### B-P1-a — `debrief` (notes coach privées) fuit vers les athlètes via le GET event normal
`event/serializers.py` (fields + `to_representation`). Le endpoint `GET events/{id}/debrief/`
est bien manager-only, MAIS `debrief` est dans `EventSerializer.fields` et **n'est pas
redacté** dans `to_representation` (qui ne masque que total/goal/rounds/ai_athlete_brief/
training_richtext). Tout athlète actif récupère les notes coach via le `GET events/{id}/`
ordinaire. L'écriture est bien manager-gated → disclosure en lecture seule, mais réelle.
**Fix (sans migration) :** masquer `debrief` (`data["debrief"]=""`) pour les non-managers
dans `to_representation`, comme `ai_athlete_brief`. + test athlète.

### B-P1-b — `event-templates/` liste : `rounds.count()` par ligne (1+N)
`event/serializers.py` `EventTemplateSerializer.get_rounds_count` + `EventTemplateViewSet.get_queryset`
(seulement `select_related`). 1 requête liste + 1 COUNT par template.
**Fix (sans migration) :** `.annotate(rounds_count=Count("rounds"))` + champ `IntegerField`.

### B-P1-c — `team-templates` (frontend) peut perdre des templates (pagination)
`features/teams/team-templates` appelle `eventTemplatesList({})` (1ʳᵉ page) puis filtre par
team côté client — le client généré n'expose pas `?team` (le filtre backend n'est pas déclaré
au schéma). Un manager multi-équipes peut voir des templates manquer au-delà de la page 1.
**Fix :** déclarer le filtre `team` sur le `EventTemplateViewSet` (`@extend_schema`/filterset) →
regen client → `eventTemplatesList({ team })`, retirer le filtre client.

### B-P1-d — onglet debrief (frontend) non lazy-monté → fetch à chaque ouverture
`events-detail.component.html` rend `<app-event-debrief>` sans le garde
`@if (activeTab() === 'debrief')` (contrairement aux onglets teams-detail). PrimeNG instancie
le panneau immédiatement → `eventsDebriefRetrieve` part à chaque ouverture event-detail manager.
**Fix :** envelopper dans `@if (activeTab() === 'debrief')`.
